# WinUI 3 剪贴板管理器重构设计

日期：2026-11-10
状态：方案已由用户确认并完成规格审阅
项目：Windows 剪贴板管理器

## 1. 目标与原则

本次是面向长期使用和维护的整体重构，不是局部换肤。目标是交付一个观感原生、响应迅速、剪贴板数据可信赖、更新过程清楚且失败可恢复的 Windows 桌面应用。

设计原则：

1. UI 采用 WinUI 3 与 Fluent 视觉；重做主窗口和更新中心，不沿用现有 WPF 页面结构。
2. 历史、剪贴板、文件、数据库、更新等职责与 UI 解耦，核心规则可独立测试。
3. 自动检查不等于自动下载；下载由用户启动，校验完成后按用户选择的 gpt++ 式流程自动安装并重启。
4. 用户历史优先：迁移有备份、可重试、可验证；更新器永远不得操作用户数据目录。
5. 从干净源码仓库即可开发、测试、打包和发布；不依赖个人私钥、代码签名证书或开发者电脑上的私有材料。
6. 以测试、故障注入和可观察状态验证安全性，不以“窗口看起来正常”替代正确性。

## 2. 已确认的产品与交互

### 2.1 工作台

采用单一主窗口和左侧导航：

- **历史**：最近复制的全部内容。
- **收藏**：已收藏的记录；收藏是 UI 用语。旧数据中的 `IsPinned` 在导入时映射为收藏。
- **更新中心**：版本状态、发行说明、检查操作、下载进度和错误恢复信息。
- **设置**：主题、容量限制、自动检查、托盘、置顶与数据目录等偏好。

历史工作区包含搜索、全部/文本/图片筛选、虚拟化记录列表，以及较宽布局中的详情预览。窄窗口收起预览，选中记录后在单栏详情中查看；宽窗口恢复列表和预览并排。详情始终可以查看并复制完整文本或图片，而非仅显示列表摘要。

浅色、深色、跟随系统三种偏好继续支持。所有页面共享 Fluent 资源和设计令牌；加载、空结果、错误、焦点和键盘操作都应有一致反馈与可访问名称。

### 2.2 收藏语义

- 用户界面统一使用“收藏 / 已收藏 / 取消收藏”，不使用“固定”表示记录收藏。
- 收藏记录不会被自动容量清理移除。
- 用户主动删除单条记录或执行清空时，收藏记录也会删除，并在确认信息中明确说明。
- 窗口置顶独立称为“窗口置顶”，与收藏不混淆。

### 2.3 保留的日常能力

- 全局快捷键 `Ctrl+Shift+Space` 唤起并激活工作台。
- 历史焦点下支持方向键选择、Enter 和 Ctrl+C 复制；搜索框中的常规文本快捷键保持正常。
- 暂停/恢复剪贴板采集、置顶窗口、托盘后台运行、删除、清空、容量上限、文本/图片详情与图片缩放继续提供。
- 文本与图片只在本地采集和保存，不将历史内容发送到更新服务或日志。

## 3. 技术与模块边界

目标桌面 UI 为 WinUI 3，目标运行时为 .NET 10，发行目标为 Windows x64。推荐拆分为以下职责层，具体项目/程序集命名在实施计划中确定：

### 3.1 Presentation / App

WinUI 3 主窗口、导航、页面、主题资源、对话框、视图模型和命令。使用 MVVM；页面不直接负责 HTTP、数据库事务、剪贴板解析或安装文件替换。应用级状态和服务通过依赖注入统一组合。

### 3.2 Core

不依赖 WPF/WinUI 控件类型，负责：

- 记录与设置模型、容量/收藏规则、去重和查询契约；
- SQLite schema 版本与迁移；
- 存储事务、持久化错误分类和备份/恢复规则；
- 更新状态模型、版本比较和可测试的更新决策。

图片跨层使用明确的字节/像素表示与文件句柄/路径，不把 `BitmapSource` 等 WPF 类型带入 Core。

### 3.3 Windows Platform Adapters

承接原生 Windows 功能：剪贴板格式读取与写入、剪贴板变化通知、STA 工作线程、图片编解码、全局快捷键、系统托盘、窗口句柄和系统主题适配。适配层提供稳定接口，WinUI 生命周期和 HWND 的具体实现集中在此处。

### 3.4 Update Worker

更新应用进程与 UI 进程分离。WinUI 应用负责呈现状态、下载和验证；应用退出后由独立 helper 持有更新互斥锁、写事务日志、替换受管理的程序文件、启动新版并等待健康确认。此边界避免运行中的 EXE/DLL 被自身替换。

## 4. 数据与迁移

### 4.1 目标数据布局

保留用户数据根目录 `%LOCALAPPDATA%\\ClipboardManager`，迁移后至少包含：

- `clipboard.db`：记录、设置、收藏标志及 schema 版本；
- `images\\*.png`：规范化的本地图片内容；
- `app.log` 与轮转日志；
- 一次迁移期间产生的只读 JSON 备份/迁移标记。

SQLite 为唯一运行时权威来源，记录、应用设置与主题偏好均存于数据库；旧 `theme.json` 只在首次迁移导入一次并保留备份，不再双写两个权威来源。

### 4.2 JSON → SQLite 一次性导入

启动顺序为：获得单实例锁 → 检测并恢复未完成的应用更新 → 打开/建立数据库 → 执行 schema 迁移 → 导入现有 `history.json`、主题偏好与图片引用 → 验证 → 启动剪贴板监听和主界面。

迁移要求：

- 在目标数据目录内先创建原 JSON 与主题配置的可恢复备份；原文件不删除。
- 使用 SQLite 事务；导入失败则整体回滚，错误展示修复/重试建议，不启动可能写空数据的覆盖流程。
- 导入记录 ID、类型、文本、原始时间、哈希、图片文件名/尺寸、收藏状态、全部现有设置和待删除图片队列。
- 导入后核对记录数量、有效图片引用、收藏数量和关键设置；只有事务提交并验证成功才写迁移完成标记。
- 标记写入具备幂等性；进程在任一迁移步骤中断后可安全再次启动，不重复插入或丢弃记录。
- 保留旧 JSON 备份，直到后续版本有明确清理策略；卸载程序默认也不删除用户数据。

### 4.3 搜索与性能

保持原有大小写不敏感的内容包含匹配语义，不能悄悄改成仅匹配关键词/前缀。SQLite 使用索引方案加速常见子串搜索，并为过短查询提供正确回退路径。用中文、英文、大小写、短查询、长文本和特殊字符做一致性回归测试；以有代表性的几千条文本及图片记录测量而非仅根据理论选型。

列表使用 WinUI 虚拟化；单条记录变化尽量局部更新，不全量重建整个列表。图片缩略图异步加载，限制并发与尺寸，离开视口或页面销毁时取消并释放资源。数据库操作、哈希和解码不得阻塞 UI Dispatcher。

## 5. 更新中心与更新管线

### 5.1 用户可见行为

- 更新中心是主窗口一级页面，不再打开独立的旧式更新覆盖窗口。
- 显示当前版本、可用版本、简明发行说明、下载体积、最近检查时间、进度、校验状态及错误后的恢复操作。
- 发现更新时用导航徽标/非阻塞提示告知，不强制切页或弹窗打断工作。
- 保留“自动检查更新”开关。启用时首次检查约在启动 20 秒后，之后约每 60 分钟检查；检查不触发下载。
- 用户点击“下载并更新”后开始下载。可取消的阶段提供取消，取消后清除不完整暂存文件；下载与验证期间应用仍可正常使用。
- 验证通过后短暂显示“正在准备重启”，然后自动退出、应用更新并重新打开；不再要求第二次确认重启。

### 5.2 状态模型

`Idle → Checking → UpToDate | Available → Downloading → Verifying → Applying → StartupHealthCheck → Complete`。

各可恢复失败状态保留清楚的阶段与错误分类：检查网络失败、下载失败、校验失败、空间不足、安装目录不可写、进程未能退出、替换失败、启动确认超时。用户可以重试安全的阶段；一旦 helper 开始事务性替换，不允许 UI 取消造成半更新。

### 5.3 来源、完整性与无秘密要求

- 只检查本项目的正式 GitHub Release 与明确允许的 HTTPS 附件源；校验发布标签、版本、平台、清单字段、路径、文件大小、压缩大小与磁盘空间。
- 每个下载文件在解压写入暂存区时校验清单 SHA-256；HTTPS、固定仓库/附件域验证、路径限制和文件校验均为发布验证的一部分。
- **不引入必须由开发者持有的私钥、签名证书或个人 token。**干净克隆可构建、测试、打包；发布仅使用用户正常拥有的 GitHub 仓库权限及工作流所需的标准最小权限。
- 这意味着文件校验可以发现传输损坏和附件不匹配，但不能单独防御 GitHub 仓库/发布权限被攻破后恶意替换清单与文件。此威胁边界需记录在使用/安全说明中。今后可加可选的发布证明，但绝不能成为构建、打包或发布的硬依赖。
- 日志记录错误阶段、版本、路径和结果，不记录剪贴板文本/图片内容、凭证或完整网络敏感头。

### 5.4 暂存、回滚和健康确认

- 更新只操作清单管理的程序文件；永不触碰数据库、图片目录、主题/历史数据、用户文件或卸载数据。
- 下载先写入专用工作区并完成全部校验，然后生成经过校验的操作清单和事务日志。校验未通过不修改当前应用。
- 独立 helper 等待应用进程身份与退出，再同盘备份/替换；逐步记录进度，使异常退出后可判定继续、恢复或清理。
- 新版启动后，只有完成数据库打开/迁移、关键服务初始化、主窗口构造并写入健康标记，事务才算完成；超时/异常则恢复所有旧文件并启动旧版。
- 更新完成后再删除备份和暂存区；恢复失败时保留工作区并给出可诊断路径，不做破坏性清理。

### 5.5 从现有 WPF 版本切换

WinUI 首发必须明确验证从当前 WPF 文件布局迁移。优先保持 `AppPaths` 用户目录、可启动入口和增量清单边界可兼容，使现有更新器能安全下载完整的 WinUI 首发差异；新 helper/launcher 需要能启动 WinUI 进程并等待其健康标记。若隔离端到端测试不能证明 WPF → WinUI 的在地更新安全，则首发明确要求一次完整安装器覆盖/重装，而不是冒险执行不兼容的增量更新。无论路径如何，用户数据目录与安装器文件操作严格分离。

## 6. 发行、开发和发布

- 保留两种正式资产：**用户级安装版**与**便携 ZIP**；两者来自同一构建产物/相同应用文件清单并使用同一更新体验。
- 采用可自包含运行的 WinUI 发布形式，不要求用户另外安装 .NET SDK/运行时；安装默认不要求管理员权限。具体 Windows App SDK 打包属性在实施计划和首个 CI 验证中确定。由于不要求代码签名私钥/证书，Windows 仍可能显示未知发布者提示；发布提供 SHA-256 校验文件，不绕过系统安全提示。
- 安装版继续支持升级、覆盖安装与卸载；卸载移除程序和快捷方式但不删用户历史。便携版从可写目录启动时可自更新；不可写时安全失败并引导用户使用安装器或手动替换，不申请管理员权限。
- 仓库应包含完整解决方案、核心库、WinUI UI、Windows 适配、更新 helper、数据库迁移、构建/打包脚本、CI、测试与必要说明。干净 Windows 开发环境只需文档声明的公开 SDK/工具，不需任何个人私钥或开发者机器上的隐藏文件。
- Release 工作流使用最小化权限；先测试、构建、生成两种包、校验清单与哈希、运行安装/升级/卸载验证；所有检查成功后再上传/发布。拒绝无意覆盖现有版本。

## 7. 错误处理、可访问性和质量

- 所有异步操作有生命周期、取消和异常观察；页面关闭后不得继续访问卸载控件。
- 向用户展示可理解的简短原因和有效恢复动作，技术细节及关联 ID 写入本地日志。
- 键盘焦点顺序清晰，Tab/Shift+Tab 行为合理；按钮有可访问名称，选中、收藏、暂停和更新阶段不只靠颜色传达。
- 支持窗口动态缩放、高 DPI、键盘导航、Windows 主题切换和文本放大；窄窗口不得横向裁剪关键操作。
- 剪贴板上限、剪贴板占用重试、图片像素上限、原生格式兼容和单实例行为保留为安全回归。

## 8. 验收标准

### 8.1 干净重建和秘密扫描

1. 从干净 Git 克隆，在文档声明的 Windows SDK/工具环境完成 restore、build、测试和本地两种包构建；不提供、也不访问任何私人签名密钥、证书或 PAT。
2. CI 使用标准仓库令牌权限发布两种资产；源代码扫描确认没有个人密钥、个人路径或用户剪贴板样本。

### 8.2 数据迁移

1. 从隔离的真实格式 JSON/PNG 样例导入，核对数量、文本、哈希、顺序、时间、收藏、设置和图片字节/尺寸。
2. 在备份、数据库创建、导入、验证与完成标记各阶段注入进程终止/磁盘错误；每种情况下旧 JSON 与图片仍可恢复，重启后可安全重试。
3. 新旧应用的持久数据路径保持一致；升级、覆盖安装、卸载不删除用户数据。

### 8.3 UI 与功能

1. 在窄、默认、宽窗口以及 100%/150%/200% 缩放检查工作台、收藏、详情、设置和更新中心。
2. 验证主题、空/加载/错误状态、键盘焦点、辅助技术名称与 Ctrl+Shift+Space 等现有快捷操作。
3. 复制文本、截图和图像；验证保存、去重、全文复制、收藏、自动容量清理、手动删除与重启恢复。
4. 对代表性几千条记录，验证虚拟化、搜索响应、局部刷新和图片异步释放；性能结论记录环境与指标。

### 8.4 更新故障注入

用隔离安装副本覆盖“无更新、自动检查关闭、手动检查、用户开始/取消下载、断网、限速、清单无效、文件丢失/超长/哈希不符、磁盘不足、无写权限、主进程不退出、替换中断、健康标记超时、回滚中断、升级后清理”路径。证明未完成验证前不改程序；失败后旧版可启动；数据目录在所有路径哈希/内容保持不变；成功路径展示正确进度并按策略自动重启。

### 8.5 发布与迁移

发布 CI 对安装版/便携版分别执行全新启动、覆盖升级和必要的卸载流程；验证 WPF → WinUI 首发选择的升级路径。如果在地迁移无法通过同一套故障测试，则必须验证一次性安装器重装路径，并明确告知用户，不能静默声称可无缝升级。

## 9. 实施分阶段

1. **新解决方案骨架与基线**：WinUI 3 启动、依赖组合、日志与错误边界，确认干净构建。
2. **Core/Windows 适配分离**：先建立接口和旧行为测试，再迁移剪贴板、图片、历史和系统集成。
3. **SQLite 与一次性导入**：事务、schema 版本、备份、幂等恢复和中文搜索回归先行。
4. **Fluent 工作台**：导航、历史/收藏/详情、设置、响应式布局、主题、键盘与可访问性。
5. **更新中心与 helper**：实现自动检查、用户启动下载、完整校验、无私钥发布、事务替换/健康确认/回滚。
6. **双包、WPF 迁移和发行 CI**：完成包验证与故障注入；只有旧行为达到验收门槛才替换正式发布入口。

## 10. 明确不做

- 不静默下载，不在未经用户点击的情况下安装。
- 不在首发中上传、同步或远程处理剪贴板历史。
- 不让签名私钥、代码签名证书、个人访问令牌或个人电脑私有环境成为开发/打包/发布前提。
- 不删除既有数据来简化 SQLite 迁移；不在更新失败时清理用户数据。
- 不为视觉效果牺牲文本可读性、键盘可操作性或低性能机器上的响应。
