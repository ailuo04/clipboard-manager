# 剪贴板

Windows 11 中文桌面剪贴板管理器。自动保存文本、截图和图片历史，支持全文搜索、固定记录、窗口置顶与全局快捷键。基于 .NET 8 WPF 和 Win32 API，没有第三方 NuGet 依赖，不使用浏览器剪贴板轮询；历史仅存本机，不上传剪贴板内容。

## 下载与使用

在仓库的 [Releases](../../releases) 页面选择 Windows 11 x64 版本：

- 安装版：下载 `ClipboardManager-0.0.2-win-x64-setup.exe`，运行中文安装向导。默认安装到当前用户的 `%LOCALAPPDATA%\Programs\ClipboardManager`，创建开始菜单快捷方式；“创建桌面快捷方式”和安装完成页的“启动剪贴板”默认勾选，可手动取消，重装时也使用这两个默认值。支持从 Windows“设置 → 应用 → 已安装的应用”卸载。
- 便携版：下载 `ClipboardManager-0.0.2-win-x64.zip`，完整解压后双击 `ClipboardManager.exe`。

两种版本均自带运行环境，不需要管理员权限，不必另装 .NET SDK 或运行时。安装版与便携版共用历史数据，不能同时运行；安装、升级和卸载均不删除历史。仓库现已公开，任何人都可以下载正式发行版。

首次运行可能出现 Windows 未知发布者提示，应用尚未代码签名。请确认来源并核对同版本 `.sha256` 文件，不要关闭系统安全防护。在 PowerShell 中校验：

```powershell
Get-FileHash .\ClipboardManager-0.0.2-win-x64.zip -Algorithm SHA256
Get-Content .\ClipboardManager-0.0.2-win-x64.sha256
Get-FileHash .\ClipboardManager-0.0.2-win-x64-setup.exe -Algorithm SHA256
Get-Content .\ClipboardManager-0.0.2-win-x64-setup.sha256
```

完整操作、升级和卸载说明见 [使用说明](docs/USAGE.md)，当前版本介绍见 [发行说明](RELEASE_NOTES.md)。

## 功能概览

| 功能 | 作用 |
| --- | --- |
| 文本、截图与图片历史 | 自动保存新复制的内容，重启后继续使用 |

## 从源码运行

本机已经构建好，可直接双击：

```text
bin\Release\net8.0-windows\ClipboardManager.exe
```

也可以在项目目录的 PowerShell 7 中运行：

```powershell
.\Start.ps1
```

程序只在窗口运行、监听未暂停时采集新发生的复制操作。最小化后继续监听；关闭窗口会释放监听器并退出。不在启动或恢复监听时补抓当前剪贴板，因此暂停期间复制的内容不会被补记。

## 构建

有 .NET 8 或更新 SDK 时使用标准命令：

```powershell
dotnet build .\ClipboardManager.csproj --configuration Release
dotnet run --project .\ClipboardManager.csproj
```

没有 SDK、但已安装 .NET 8 Windows Desktop Runtime 和 PowerShell 7 时，项目提供不下载、不安装依赖的替代构建：

```powershell
.\build.ps1
```

脚本优先使用已有 SDK；没有 SDK 时，使用 PowerShell 7 已有的 Roslyn 编译器和本机 .NET 8 Windows Desktop Runtime。XAML 作为嵌入资源加载，两条构建路径使用同一套应用代码和界面。备用构建还利用 Windows 自带的 .NET Framework 编译器生成无控制台启动器；主程序仍运行在 .NET 8 WPF 上。单独执行 `build.ps1` 不是自包含发行包，换机器需要运行时；对外分发请使用下面的打包脚本。

## 打包与发布

### 应用内增量更新

v0.0.2 是首个包含应用内增量更新器的版本；v0.0.1 不包含此功能，需要先手动升级一次。

主界面新增“应用更新”图标，设置页也可打开。默认在启动约 5 秒后及运行期间每 6 小时检查一次正式发行版，可在设置中关闭。检查仅请求 GitHub 版本信息和文件清单；发现新版后显示下载量，用户确认后才下载，校验完成后保存当前操作、退出并更新，再自动启动。

更新是**文件级增量**，不是完整 ZIP 或安装包替换：逐个比较本地文件的 SHA256，只获取新增或改变文件对应的 GZip 附件，删除新版不再包含且未被手动修改的旧发行文件。未变化的 .NET 运行环境不下载、不复制、不改写。若某个 DLL 改动，会下载该 DLL 的完整压缩内容，不是二进制字节差分；运行环境真正升级时，其变化文件也需要下载。

压缩数据直接解压写入程序目录内的临时工作区，不额外保存压缩包。只暂存本次变动，原文件在同盘移动备份；新版成功打开后删除备份和临时文件，不保留整份旧版本。断网、取消或校验失败不修改原程序；应用替换中断时，独立启动器根据事务记录恢复。仅管理发行清单中的程序文件，不更新历史数据、图片、设置、卸载器或用户自行添加的文件。安装版的卸载入口版本会同步更新，卸载时也会清理增量新增的发行文件。

更新源固定为本项目 GitHub Releases，公开仓库不需要令牌。私有仓库可在更新窗口的“私有仓库访问”中保存访问令牌；建议使用只授权此仓库且 **Contents: Read-only** 的细粒度令牌。令牌保存在 Windows 凭据管理器，可在同一窗口删除，不写入历史 JSON、发行包或日志。请求 GitHub 会产生常规网络访问记录，但不上传剪贴板内容。下载经 HTTPS 和逐文件 SHA256 校验，尚无独立发行签名，仍需信任 GitHub 仓库及发布权限的管理。

旧发行版不含更新器，必须先手动升级一次到含本功能的发行版。此后新发行版必须由新版发布流程生成更新清单和文件附件，且打包方式保持一致；缺少附件、无权限或打包方式改变时明确报错，**绝不退回全量更新**。自动更新需要程序目录可写，不申请管理员权限。

```powershell
.\package.ps1 -Version 0.0.2
.\installer.ps1 -Archive .\dist\ClipboardManager-0.0.2-win-x64.zip -Version 0.0.2
```

在 `dist` 生成 Windows x64 便携 ZIP、SHA256、增量更新清单及逐文件压缩附件。有 SDK 时使用标准 `dotnet publish --self-contained true`；没有 SDK 时，编译应用并将本机匹配版本的 .NET 8 Core、Windows Desktop 和 hostfxr 复制到包内私有 `runtime` 目录，保留 .NET 许可声明，不安装或修改系统运行环境。包内 `release.json` 记录应用版本、运行环境版本和构建方式；离线打包不会下载最新安全补丁，正式维护应定期重发包含更新运行环境的版本。

脚本拒绝覆盖同版本文件，避免误替换已发布附件。打包临时目录在完成或失败后清理；用户的历史与图片不会进入发行包。发行包无需依赖用户机器上的全局 .NET，但不能只复制其中的 EXE。

`installer.ps1` 校验输入 ZIP 和版本后，使用已有 Inno Setup 编译器构建中文安装版，同时生成独立 SHA256 文件；不会下载或安装构建工具。当前本机没有 Inno Setup，可使用预装该工具的 GitHub Windows 构建环境。安装包使用固定应用标识，支持原目录覆盖升级；程序正在运行时要求先退出。卸载只移除安装文件、快捷方式和卸载注册信息，不删除用户历史。

GitHub Actions 工作流 `.github/workflows/release.yml` 支持推送 `v0.0.2` 形式的标签或在 Actions 手动填写版本号。工作流在 Windows 上构建标准自包含版本和中文安装包，验证安装、重装、启动、卸载及数据保留，再上传 ZIP、安装 EXE 和各自的 SHA256；附件上传完成后才公开 Release，已存在的版本不会被覆盖。给既有版本补充安装包可运行 `.github/workflows/installer.yml`，它复用该版本已经发布的 ZIP，不移动标签、不替换已有附件。工作流使用 GitHub 自动提供的令牌，不需要在源码中保存密钥。发布新版本前请同步更新项目版本、默认脚本版本和 `RELEASE_NOTES.md`；仓库可见性不会被工作流修改。

## 功能与规则

- 程序文件、任务栏和窗口统一使用绿色剪贴板图标，内嵌透明背景的多尺寸 ICO，兼容标准 SDK 与本地备用构建。
- 默认窗口为 360×520，最小为 320×360；根据窗口宽度与高度自动切换紧凑布局，放大后恢复正常布局。标题栏使用 WPF WindowChrome，保留系统最小化、最大化、关闭按钮，以及拖动、双击最大化和边缘缩放。
- 文本列表与等比例图片卡片按采集时间倒序排列，类型、时间、字符数或图片尺寸合并显示。紧凑布局的文本预览最多三行，图片缩略图高度为 104 像素；预览不改变实际复制的完整内容。
- 点击记录主体或右侧的复制图标复制完整内容；其余按钮分别为固定、详情、删除。文本详情可以选择、滚动查看完整文本，图片详情支持适应窗口及缩放。
- 历史列表获得焦点后，可用 Up/Down 选择记录，Enter 或 Ctrl+C 复制当前记录；选中项会滚动到可视区域。搜索框中的 Ctrl+C 保持正常文本复制，Up/Down 可转入历史列表。
- Ctrl+Shift+Space 是全局唤起快捷键，可显示、恢复或激活主窗口，并聚焦历史列表（没有记录时聚焦搜索框）。使用 Windows 消息注册，不轮询，也不占用 Win+V；冲突时显示提示并写入日志，应用仍可正常使用。关闭时注销快捷键。
- 标题栏最小化按钮左侧的图钉可一键切换窗口置顶，启用后高亮；与设置中的“窗口置顶”同步，默认关闭，保存成功后立即生效，重启后保留。窗口置顶与固定历史记录相互独立；旧 JSON 没有该字段时默认不置顶，保存失败时保留旧配置与窗口状态。
- 搜索匹配完整文本，而不是仅匹配预览；图片在有搜索词时不显示。支持全部、文本、图片筛选。
- 相同文本按完整 UTF-8 内容哈希去重；相同图片按标准化像素和尺寸哈希去重，不依赖文件名、PNG 编码元数据或来源。重复复制更新原记录时间，并保留固定状态。
- 监听通知防抖为 100 ms，短时间内的密集变化可能合并为最后一次内容。应用回写携带进程专用标记，不会触发历史反馈循环。
- 默认最多 500 条记录、512 MB 内容数据。容量计算包括文本 UTF-8 字节与 PNG 文件大小，不包含 JSON 格式开销与日志。自动清理先移除最早的未固定记录；固定记录不自动清理，所以固定内容本身可超过限制，界面会提示。
- 清空包含固定记录，操作前需确认；单条删除和清空均删除对应图片。文件被占用或无权限删除时，显示错误提示并持久化待删除队列，在后续操作或重启时重试。
- 应用单实例运行，不提供开机启动或系统托盘。

## 图片来源

读取的是系统剪贴板中的实际数据：注册格式 `PNG`、`image/png`、`JFIF`、`JPEG`、`image/jpeg`、`BMP`、`image/bmp`，以及标准 `CF_DIBV5`、`CF_DIB`、`CF_BITMAP`。注册格式解码失败时会继续尝试标准位图数据。DIB 会补齐 BMP 文件头，并处理调色板、位掩码、正负高度及 DIBV5 alpha。

因此截图所使用的 DIB/DIBV5/Bitmap 数据不需要文件路径。文件资源管理器复制的图片则通过 `CF_HDROP` 获取来源路径后立即读取像素、重新编码并保存，历史记录不依赖源文件继续存在。一次复制多个图片文件时，当前仅采集其中第一个支持的图片文件。

单次剪贴板数据读取上限为 128 MB、Unicode 文本数据上限为 8 MB、解码图片上限为 4000 万像素。超过上限会提示错误，防止异常数据导致过量内存分配。GIF/TIFF 只保留首帧；WebP 文件是否可读取决于系统可用的 WIC 解码器，不属于保证范围。

## 数据与日志

```text
%LOCALAPPDATA%\ClipboardManager\
  history.json       文本、图片索引、设置、待删除队列
  images\*.png       持久图片像素
  app.log            诊断日志
  app.log.old        上一次轮转日志
```

历史元数据先写入同目录临时文件，再原子替换正式文件；成功后才发布内存状态和删除旧图片。失败时保留旧状态，清理本次新增图片。损坏或不可读的历史文件不会直接当作空记录覆盖，应用会显示错误与重试入口。只会在成功加载有效索引后清理无引用图片。

剪贴板操作在独立 STA 线程执行；系统剪贴板占用时有限次数退避重试。图片解码、编码、文件读写与缩略图生成不在界面线程上运行。列表启用虚拟化，可见图片异步加载，离开视口后释放缩略图。

日志包含操作上下文、格式名、错误码和异常堆栈，不主动写入完整剪贴板文本。日志约 2 MB 后轮转一次。设置中可打开数据目录或日志。

所有历史均保存在本机，不进行网络上传；文本和图片没有额外加密。复制敏感信息前可暂停监听，并按需删除历史。此工具不等同于安全密码管理器。
