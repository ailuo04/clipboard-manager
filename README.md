# 剪贴板

Windows 11 中文桌面剪贴板管理器。自动保存文本、截图和图片历史，支持全文搜索、固定记录与全局快捷键；平时是一个 240×40 的置顶胶囊，需要时展开成 300×400 的紧凑面板。基于 .NET 8 WPF 和 Win32 API，没有第三方 NuGet 依赖，不使用浏览器剪贴板轮询；历史仅存本机，不上传剪贴板内容。

## 下载与使用

在仓库的 [最新正式版](../../releases/latest) 页面选择 Windows 11 x64 版本：

- 安装版：下载 `ClipboardManager-0.0.13-win-x64-setup.exe`，运行中文安装向导。默认安装到当前用户的 `%LOCALAPPDATA%\Programs\ClipboardManager`，创建开始菜单快捷方式；“创建桌面快捷方式”和安装完成页的“启动剪贴板”默认勾选，可手动取消，重装时也使用这两个默认值。支持从 Windows“设置 → 应用 → 已安装的应用”卸载。
- 便携版：下载 `ClipboardManager-0.0.13-win-x64.zip`，完整解压后双击 `ClipboardManager.exe`。

两种版本均自带运行环境，不需要管理员权限，不必另装 .NET SDK 或运行时。安装版与便携版共用历史数据，不能同时运行；安装、升级和卸载均不删除历史。仓库现已公开，任何人都可以下载正式发行版。

首次运行可能出现 Windows 未知发布者提示，应用尚未代码签名。请确认来源并核对同版本 `.sha256` 文件，不要关闭系统安全防护。在 PowerShell 中校验：

```powershell
Get-FileHash .\ClipboardManager-0.0.13-win-x64.zip -Algorithm SHA256
Get-Content .\ClipboardManager-0.0.13-win-x64.sha256
Get-FileHash .\ClipboardManager-0.0.13-win-x64-setup.exe -Algorithm SHA256
Get-Content .\ClipboardManager-0.0.13-win-x64-setup.sha256
```

完整操作、升级和卸载说明见 [使用说明](docs/USAGE.md)，当前版本介绍见 [发行说明](RELEASE_NOTES.md)。

## 功能概览

| 功能 | 作用 |
| --- | --- |
| 文本、截图与图片历史 | 自动保存新复制的内容，重启后继续使用 |
| 全文搜索与分类 | 从全部、文本、图片中快速定位记录 |
| 点击与键盘复制 | 复制完整内容后在目标软件粘贴，不会自动粘贴 |

| 详情预览 | 查看完整文本，缩放图片 |

## 从源码运行

本机已经构建好，可直接双击：

```text
bin\Release\net8.0-windows\ClipboardManager.exe
```

也可以在项目目录的 PowerShell 7 中运行：

```powershell
.\Start.ps1
```

程序启动后以胶囊形式停在屏幕右下角，并持续监听新发生的复制操作。收起或最小化后继续监听；设置中启用“关闭窗口时最小化到系统托盘”后，关闭窗口会保留后台监听，可从托盘菜单重新打开、暂停监听或退出。该选项默认关闭。不在启动或恢复监听时补抓当前剪贴板，因此暂停期间复制的内容不会被补记。

## 构建

有 .NET 8 或更新 SDK 时使用标准命令：

```powershell
dotnet build .\ClipboardManager.csproj --configuration Release
dotnet run --project .\ClipboardManager.csproj
```

需要同时生成无控制台启动器和更新工具时，在 PowerShell 7 中运行：

```powershell
.\build.ps1
```

脚本同样需要 .NET 8 或更新的 SDK，没有 SDK 时会直接报错。它先用 SDK 构建主程序，再利用 Windows 自带的 .NET Framework 编译器生成启动器和更新工具；主程序仍运行在 .NET 8 WPF 上。单独执行 `build.ps1` 不是自包含发行包，换机器需要运行时；对外分发请使用下面的打包脚本。

## 打包与发布

### 应用内增量更新

v0.0.2 是首个包含应用内增量更新器的版本；v0.0.3 可直接从 v0.0.2 应用内升级，v0.0.1 不包含此功能，需要先手动升级一次。

更新器通过固定地址 `https://github.com/ailuo04/clipboard-manager/releases/latest/download/latest-win-x64.json` 读取最新正式版的更新清单。固定名称清单、带版本号的清单和逐文件压缩附件与安装包一起发布在同一正式版中。下载增量文件时锁定清单中的 `v版本号`，不再查询 Release API 或旧的 `updates-v版本号` 数据区；带版本号的清单继续保留，供旧版客户端读取。

v0.0.2 曾按确认完成同版本重建，旧批次用户需重新安装一次以切换更新数据源；该问题不影响 v0.0.3 及后续版本的应用内增量更新。

主界面新增“应用更新”图标，设置页也可打开。默认在启动约 5 秒后及运行期间每 6 小时检查一次正式发行版，可在设置中关闭。检查仅下载固定地址的更新清单；发现新版后显示下载量，用户确认后才下载，校验完成后保存当前操作、退出并更新，再自动启动。

更新是**文件级增量**，不是完整 ZIP 或安装包替换：逐个比较本地文件的 SHA256，只获取新增或改变文件对应的 GZip 附件，删除新版不再包含且未被手动修改的旧发行文件。未变化的 .NET 运行环境不下载、不复制、不改写。若某个 DLL 改动，会下载该 DLL 的完整压缩内容，不是二进制字节差分；运行环境真正升级时，其变化文件也需要下载。

压缩数据直接解压写入程序目录内的临时工作区，不额外保存压缩包。只暂存本次变动，原文件在同盘移动备份；新版成功打开后删除备份和临时文件，不保留整份旧版本。断网、取消或校验失败不修改原程序；应用替换中断时，独立启动器根据事务记录恢复。仅管理发行清单中的程序文件，不更新历史数据、图片、设置、卸载器或用户自行添加的文件。安装版的卸载入口版本会同步更新，卸载时也会清理增量新增的发行文件。

更新源固定为公开仓库 `ailuo04/clipboard-manager` 的 GitHub Releases，不使用个人访问令牌。客户端检查和下载都直接访问 Release 附件，不调用 GitHub REST API，因此不消耗匿名 API 请求额度。固定清单使用 ETag 缓存；网络服务仍可能限制下载请求，不承诺无限频率访问。保留清单大小限制、路径检查、下载长度检查和逐文件 SHA256 校验。首次启用需要发布包含 `latest-win-x64.json` 的正式版；附件缺失时明确报错，不回退到 API。已安装的旧版客户端仍沿用其原有更新逻辑。

旧发行版不含更新器，必须先手动升级一次到含本功能的发行版。此后新发行版必须由新版发布流程生成更新清单和文件附件，且打包方式保持一致；缺少附件、无权限或打包方式改变时明确报错，**绝不退回全量更新**。自动更新需要程序目录可写，不申请管理员权限。

```powershell
.\package.ps1 -Version 0.0.13
.\installer.ps1 -Archive .\dist\ClipboardManager-0.0.13-win-x64.zip -Version 0.0.13
```

在 `dist` 生成 Windows x64 便携 ZIP、SHA256、增量更新清单及逐文件压缩附件。打包使用标准 `dotnet publish --self-contained true`，需要安装 .NET 8 SDK；先前的无 SDK 离线打包路径已移除，因为视图改为编译式 XAML 后必须经过 WPF XAML 编译器。包内 `release.json` 记录应用版本、运行环境版本和构建方式。

脚本拒绝覆盖同版本文件，避免误替换已发布附件。打包临时目录在完成或失败后清理；用户的历史与图片不会进入发行包。发行包无需依赖用户机器上的全局 .NET，但不能只复制其中的 EXE。

`installer.ps1` 校验输入 ZIP 和版本后，使用已有 Inno Setup 编译器构建中文安装版，同时生成独立 SHA256 文件；不会下载或安装构建工具。当前本机没有 Inno Setup，可使用预装该工具的 GitHub Windows 构建环境。安装包使用固定应用标识，支持原目录覆盖升级；程序正在运行时要求先退出。卸载只移除安装文件、快捷方式和卸载注册信息，不删除用户历史。

GitHub Actions 工作流 `.github/workflows/release.yml` 支持版本标签和手动填写版本号。在 Windows 上构建自包含程序与中文安装包，验证安装、重装、启动、卸载及数据保留后，`publish-release.ps1` 先校验固定名称清单与带版本号清单完全一致，再将安装包、两份更新清单及逐文件压缩附件上传到同一正式 Release，校验所有附件后才发布并标记 Latest。附件中包含每个发行文件的压缩内容，但客户端按本机 SHA256 对比后，只下载新增或发生变化的文件；未变化文件不传输、不重写。默认拒绝覆盖既有版本；只有明确批准后才允许同版本刷新。

## 功能与规则

- 程序文件、任务栏和窗口统一使用绿色剪贴板图标，内嵌透明背景的多尺寸 ICO，兼容标准 SDK 与本地备用构建。
- 主窗口是一个始终置顶、不可手动缩放的小组件，有两种状态：收起时是 240×40 的胶囊，显示监听状态圆点、最新一条内容的单行文字和记录条数；展开时是 300×400 的面板。首次启动停在主显示器工作区右下角；点击胶囊展开，拖动胶囊或面板左上角的手柄移动，位置保存在设置里并在下次启动时恢复（超出当前显示器工作区时自动拉回）。面板从胶囊位置展开，放不下时向工作区内偏移。右键胶囊或点击面板的菜单按钮可展开 / 收起、暂停监听、打开设置、检查更新、清空历史和退出。
- 面板在复制完成（“复制后自动收起”开启时）、按 Esc 或失去焦点时收回胶囊，并尽量把焦点还给展开前的窗口。面板上的图钉或设置中的“保持展开”开启后，失去焦点不再收起；该设置沿用原“窗口置顶”的配置字段 `alwaysOnTop`，默认关闭。设置中的“胶囊上不显示最新内容”开启后，胶囊只显示“剪贴板”和条数。
- 窗口没有标题栏。设置和应用更新以卡片形式显示在展开的面板内，窗口大小不变（从胶囊菜单打开时先展开面板）；详情页需要空间显示完整内容，打开时窗口临时放大，关闭后恢复原来的大小和位置。每个页面的标题、关闭按钮和（从设置进入更新时的）返回按钮都在卡片顶部，Esc 同样返回。右键菜单和托盘菜单跟随应用主题；Windows 11 下使用圆角与 DWM 系统背景。
- 记录按采集时间倒序排列，每条占一行：序号、图片缩略图（仅图片）、单行内容、固定标记和时间。悬停时出现完整内容或图片的预览提示，以及固定、详情、删除按钮；预览不改变实际复制的完整内容。
- 点击记录复制完整内容。文本详情可以选择、滚动查看完整文本，图片详情支持适应窗口及缩放。
- 历史列表获得焦点后，可用 Up/Down 选择记录，Enter 或 Ctrl+C 复制当前记录；选中项会滚动到可视区域。搜索框中的 Ctrl+C 保持正常文本复制，Up/Down 可转入历史列表。
- Ctrl+Shift+Space 是全局快捷键：面板收起时展开并聚焦历史列表（没有记录时聚焦搜索框），面板已展开且在前台时收起。再次启动程序或点击托盘图标也会展开面板。使用 Windows 消息注册，不轮询，也不占用 Win+V；冲突时显示提示并写入日志，仍可点击胶囊展开。关闭时注销快捷键。胶囊获得键盘焦点时，Enter、空格或向下键展开面板。
- 搜索匹配完整文本，而不是仅匹配预览；图片在有搜索词时不显示。支持全部、文本、图片筛选。
- 相同文本按完整 UTF-8 内容哈希去重；相同图片按标准化像素和尺寸哈希去重，不依赖文件名、PNG 编码元数据或来源。重复复制更新原记录时间，并保留固定状态。
- 监听通知防抖为 100 ms，短时间内的密集变化可能合并为最后一次内容。应用回写携带进程专用标记，不会触发历史反馈循环。
- 默认最多 500 条记录、512 MB 内容数据。容量计算包括文本 UTF-8 字节与 PNG 文件大小，不包含 JSON 格式开销与日志。自动清理先移除最早的未固定记录；固定记录不自动清理，所以固定内容本身可超过限制，界面会提示。
- 清空包含固定记录，操作前需确认；单条删除和清空均删除对应图片。文件被占用或无权限删除时，显示错误提示并持久化待删除队列，在后续操作或重启时重试。
- 应用单实例运行；深色、浅色或跟随系统主题可在设置中切换并即时预览，保存到 `theme.json`。系统托盘后台运行可在设置中启用，默认关闭；托盘菜单可重新打开窗口、暂停或恢复监听、退出程序。程序不提供开机自启。

## 图片来源

读取的是系统剪贴板中的实际数据：注册格式 `PNG`、`image/png`、`JFIF`、`JPEG`、`image/jpeg`、`BMP`、`image/bmp`，以及标准 `CF_DIBV5`、`CF_DIB`、`CF_BITMAP`。注册格式解码失败时会继续尝试标准位图数据。DIB 会补齐 BMP 文件头，并处理调色板、位掩码、正负高度及 DIBV5 alpha。

因此截图所使用的 DIB/DIBV5/Bitmap 数据不需要文件路径。文件资源管理器复制的图片则通过 `CF_HDROP` 获取来源路径后立即读取像素、重新编码并保存，历史记录不依赖源文件继续存在。一次复制多个图片文件时，当前仅采集其中第一个支持的图片文件。

单次剪贴板数据读取上限为 128 MB、Unicode 文本数据上限为 8 MB、解码图片上限为 4000 万像素。超过上限会提示错误，防止异常数据导致过量内存分配。GIF/TIFF 只保留首帧；WebP 文件是否可读取决于系统可用的 WIC 解码器，不属于保证范围。

## 数据与日志

```text
%LOCALAPPDATA%\ClipboardManager\
  history.json       文本、图片索引、设置、待删除队列
  theme.json         深色、浅色或跟随系统的主题偏好
  images\*.png       持久图片像素
  app.log            诊断日志
  app.log.old        上一次轮转日志
```

历史元数据先写入同目录临时文件，再原子替换正式文件；成功后才发布内存状态和删除旧图片。失败时保留旧状态，清理本次新增图片。损坏或不可读的历史文件不会直接当作空记录覆盖，应用会显示错误与重试入口。只会在成功加载有效索引后清理无引用图片。

剪贴板操作在独立 STA 线程执行；系统剪贴板占用时有限次数退避重试。图片解码、编码、文件读写与缩略图生成不在界面线程上运行。列表启用虚拟化，可见图片异步加载，离开视口后释放缩略图。

日志包含操作上下文、格式名、错误码和异常堆栈，不主动写入完整剪贴板文本。日志约 2 MB 后轮转一次。设置中可打开数据目录或日志。

所有历史均保存在本机，不进行网络上传；文本和图片没有额外加密。复制敏感信息前可暂停监听，并按需删除历史。此工具不等同于安全密码管理器。
